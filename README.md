# MariFindX

**AI-Powered Marine Oil Spill Detection and Vessel Attribution System**
SIH26143 — leveraging satellite imagery to determine oil spills at sea, with AIS
correlation to identify the vessel most likely associated with the spill.

---

## What this is

A runnable end-to-end prototype, not a mockup. The chain is:

```
Sentinel-1 SAR (VV+VH, Sigma0 dB)
   -> preprocessing + patching
   -> Attention U-Net segmentation
   -> predicted mask
   -> georeferenced polygon (GeoJSON, WGS84)
   -> spill geometry (area / axes / orientation)
   -> backward Lagrangian drift + Monte Carlo
   -> probable-origin probability zone + release window
   -> AIS ingestion (MarineCadastre CSV or synthetic)
   -> spatial + temporal candidate filter
   -> transparent weighted correlation scoring
   -> ranked association + investigation dashboard + 3D time-lapse
```

Every stage runs locally with no API keys and no external services.

### Honest scope

Read this before quoting any number from this repo.

- **No pretrained oil-spill weights ship here.** You must train a model.
- The bundled `data/raw` scenes are **synthetic SAR-like rasters** generated by
  `scripts/make_demo_data.py`. They exist so the pipeline can be executed and
  verified without the ~85 GB Zenodo download. **Metrics from them measure code
  correctness, not oil-spill detection skill.** Anything trained on them is
  labelled `data_provenance.synthetic: true` in `models/model_metadata.json`,
  and the dashboard shows a banner saying so.
- The drift model is decision support, not a validated operational oil-weathering
  model. No evaporation, emulsification, dispersion or Stokes drift.
- Correlation weights are prototype parameters, not calibrated constants.
- Output is a **ranked candidate association**, never a determination of legal
  responsibility.

## Quick start

### 1. Python environment

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

For CUDA, install torch from the PyTorch index instead of PyPI:

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
```

Device selection is automatic. CPU gets a smaller batch size and no AMP.

### 2. Data

**Option A — validate the pipeline immediately (no download):**

```bash
python scripts/make_demo_data.py
```

Writes ~74 synthetic georeferenced 2-band GeoTIFFs plus a demo scene.

**Option B — the real Zenodo corpus:**

```bash
python scripts/download_dataset.py --list     # records and sizes
python scripts/download_dataset.py --manual   # layout instructions
python scripts/download_dataset.py --check    # verify what you placed
```

| Part | Record | Contents | Goes to |
|------|--------|----------|---------|
| I | [8346860](https://zenodo.org/records/8346860) | oil train/val + masks | `data/raw/oil/` |
| II | [8253899](https://zenodo.org/records/8253899) | no-oil + look-alike train/val | `data/raw/lookalike/`, `data/raw/nooil/` |
| III | [13761290](https://zenodo.org/records/13761290) | independent test set | `data/raw/test/{oil,lookalike,nooil}/` |

Expected layout:

```
data/raw/
├── oil/{images,masks}/
├── lookalike/{images,masks}/
├── nooil/{images,masks}/
└── test/
    ├── oil/{images,masks}/
    ├── lookalike/{images,masks}/
    └── nooil/{images,masks}/
```

Images and masks pair by filename stem (`scene_01.tif` ↔ `scene_01.tif` or
`scene_01_mask.tif`).

### 3. Train

```bash
# quick — subset, laptop friendly
python -m ml.train --config config.yaml --mode quick

# full — everything, GPU recommended
python -m ml.train --config config.yaml --mode full --encoder resnet34 --patch-size 512
```

Windows helpers: `scripts\train_demo.bat`, `scripts\train_full.bat`.

Useful flags: `--epochs N`, `--batch-size N`, `--encoder resnet34|efficientnet_b0|plain`,
`--patch-size N`, `--cpu`, `--resume models/last.pt`.

Outputs:

| Path | Contents |
|------|----------|
| `models/marifindx_oil_segmentation.pt` | best-Dice checkpoint |
| `models/best_iou.pt` | best-IoU checkpoint |
| `models/last.pt` | resumable |
| `models/model_metadata.json` | architecture, metrics, provenance |
| `results/training_history.csv` | per-epoch log |
| `results/training_curve.png` | loss + overlap curves |

### 4. Evaluate

```bash
python -m ml.validate --config config.yaml   # validation split
python -m ml.test --config config.yaml       # held-out Part III
```

`ml.test` writes `results/metrics.json` and ~20 figures to
`results/qualitative/`, and reports **per scenario** (oil / look-alike /
no-oil). Overall pixel accuracy is deliberately not the headline: with oil
under 1% of a scene, predicting all-background scores >99% while detecting
nothing.

### 5. Inference

```bash
python -m ml.inference --image data/demo/demo_scene.tif
```

Writes probability map, binary mask, `*_spill.geojson`, a 4-panel preview and a
detection JSON under `results/`.

### 6. Run the app

Two terminals:

```bash
# backend
uvicorn backend.main:app --reload      # http://127.0.0.1:8000  (docs at /docs)

# frontend
npm install
npm run dev                            # http://localhost:5173
```

Open `/investigation` and click **Run Demo Investigation**.

If no checkpoint exists the UI says so and prints the training command. It does
not fabricate a prediction.

## Model

**Attention U-Net**, encoder configurable (`resnet34`, `efficientnet_b0`, or a
dependency-free `plain` fallback).

Input is genuinely **2-channel (VV, VH)**. The encoder's first convolution is
*rebuilt* with `in_channels=2` rather than duplicating a band to fit an RGB stem.
With `pretrained: true` the new stem is seeded by averaging the RGB kernels and
rescaling for the changed fan-in; that adaptation is recorded as
`first_conv_adapted_from_rgb` in the metadata.

**Loss** — `0.5·Dice + 0.3·BCE + 0.2·Focal` (weights configurable; Tversky
available as `loss.mode: tversky`):

- Dice is region-level, so it stays informative under extreme class imbalance.
- BCE gives a dense, well-conditioned gradient that stabilises early training.
- Focal suppresses the flood of easy background pixels so updates concentrate on
  the ambiguous dark regions — the oil/look-alike boundary this task turns on.

**Leakage control** — train/val is split over whole *images*, then expanded into
patches, so patches from one scene cannot straddle the split. `ml.train` asserts
this. Part III is never touched during training.

**Look-alike handling** — look-alike and no-oil scenes are trained as negatives
with all-zero masks, so "dark" alone is not evidence of oil. At inference a
configurable guard (`inference.lookalike_guard`) demotes regions failing mean
probability, aspect-ratio or minimum-area tests.

**Confidence** is `0.7·mean + 0.3·p90` over the predicted region, not
`max(probability)` — one saturated pixel should not certify a scene.

## AIS

Reads MarineCadastre-style CSV exports, normalising column-name variants
(`BaseDateTime`/`timestamp`, `LAT`/`lat`, `VesselName`/`name`, …) into one
schema, then validates, deduplicates, sorts per MMSI and reconstructs
trajectories.

```yaml
ais:
  source: file
  file: data/synthetic/synthetic_ais.csv
```

With no file configured it falls back to a deterministic synthetic fleet. The
scenario is fixed in advance in `ais_service.generate_synthetic_ais` — one
vessel transits the origin zone inside the release window, several pass nearby,
the rest are unrelated — and is **not** tuned against ranking output. Synthetic
tracks are always surfaced as **"Synthetic AIS Demonstration Data"**.

Generate a CSV:

```bash
python data/generate_synthetic_ais.py --lat 19.26 --lon 71.80
```

## Correlation

```
S = 0.25·Proximity + 0.20·Temporal + 0.20·Trajectory + 0.20·Origin + 0.15·Drift
```

Each component is bounded to [0,1] and reported with the measurement that
produced it, so a reviewer can audit the ranking instead of trusting a number.
Weights live in `config.yaml` and can be overridden per request via
`POST /api/correlation/run`.

An optional XGBoost refinement layer activates only if a trained booster is
present; the rule-based path is always sufficient.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `Model checkpoint not found` | `python -m ml.train --config config.yaml --mode quick` |
| `No training images found` | `python scripts/make_demo_data.py` or `--manual` |
| Frontend: "Backend unreachable" | `uvicorn backend.main:app --reload` |
| 3D blank / "WebGL unavailable" | switch to 2D Map; update GPU drivers |
| Training too slow on CPU | `--encoder plain --patch-size 256 --batch-size 4` |
| CUDA not used | check `GET /api/model/status` → `cuda_available` |

## Terminology

Used deliberately: *Potential Oil Spill*, *Probable Origin*, *Simulated Drift*,
*Most Likely Associated Vessel*, *Correlation Score*, *Investigation Evidence*.

Never: *Confirmed Source*, *Confirmed Culprit*, *Legally Responsible Vessel*.
